# Irigate 0.5.0

Release date: 2026-07-28

## Highlights

Irigate can now run as a durable systemd user service. The managed unit keeps credential values out of its definition while preserving the existing connection-preserving reload behavior for valid profile-only changes.

## Added

- `irigate systemd setup --config <profile>` writes `~/.config/systemd/user/irigate.service` and a mode-`0600` `~/.config/irigate/irigate.env`, then daemon-reloads, enables, and starts the service.
- `irigate systemd sync --config <profile>` refreshes the private environment file and restarts an active service so changed referenced environment values take effect.
- `irigate systemd reload` delegates to the unit's connection-preserving reload action.
- Service-operation guidance for status, journald logs, start, stop, restart, enable/disable, synchronization, reload, and removal.

## Changed

- A fixed `irigate.service` manages one selected profile. Running setup or sync with another profile replaces the unit configuration.
- Use `systemctl --user stop irigate.service` rather than `irigate stop` for a managed broker, so systemd owns and records the service lifecycle.

## Install or upgrade

```sh
uv tool install irigate
# Existing installation:
uv tool upgrade irigate
irigate --version
```

Irigate requires Python 3.11 through 3.14. Existing foreground brokers require no profile migration. Run `irigate systemd setup --config <profile>` to adopt systemd management.

## Known limitations

- The service requires a running systemd user manager.
- One fixed `irigate.service` manages one selected profile; concurrent profiles require separate manual units.
- `systemd reload` cannot refresh process environment values. Use `irigate systemd sync` when a referenced value changes.
