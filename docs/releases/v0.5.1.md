# Irigate 0.5.1

Release date: 2026-07-29

## Highlights

Irigate 0.5.1 prevents two false outage paths: a systemd-managed uv tool now keeps the virtual environment that contains Irigate, and an MCP tool's application error no longer degrades a healthy shared upstream.

## Fixed

- Generated systemd units retain the configured interpreter path without resolving a uv tool virtual-environment symlink to its base Python executable.
- Tool-level MCP application errors remain visible to callers and per-agent metrics, but they do not increment upstream failure or crash counters or open the shared-worker degradation breaker.

## Install or upgrade

```sh
uv tool upgrade irigate
irigate --version
```

Irigate requires Python 3.11 through 3.14. No profile migration is required.

For a systemd-managed installation upgraded from 0.5.0, run this from a shell where every referenced broker environment value is set:

```sh
irigate systemd sync --config ~/.config/irigate/config.yaml
# If sync reports restarted=false:
systemctl --user start irigate.service
```

## Known limitations

- The service requires a running systemd user manager.
- `systemd sync` restarts only an active service; a stopped or failed unit requires `systemctl --user start irigate.service` after synchronization.
- One fixed `irigate.service` manages one selected profile; concurrent profiles require separate manual units.

## Verification

- Package: <https://pypi.org/project/irigate/>
- Confirm `irigate --version` reports `0.5.1`.
- For a managed broker, confirm `systemctl --user status irigate.service` reports `active (running)` and `irigate status --config ~/.config/irigate/config.yaml` reports `state=running`.
